## 本地模型与在线 API 切换

系统支持两种大模型调用方式，病历生成、病例问答和图片分析会统一使用当前选择的模型：

1. 本地模型：继续使用 llama.cpp 的 OpenAI 兼容接口。
2. 在线 API：支持 OpenAI、DeepSeek、通义千问等提供的 OpenAI 兼容 `chat/completions` 接口。

启动系统后，点击右上角“模型设置”：

- 选择“在线 API”。
- 填写完整接口地址，例如 `https://api.openai.com/v1/chat/completions`。
- 填写服务商要求的模型名称和 API Key。
- 先点击“测试连接”，成功后点击“保存并使用”。

API Key 仅保存在本机的 `data/llm_config.json` 中。该文件已经加入 `.gitignore`，不会随 Git 提交。请勿在 README、代码或截图中公开密钥。调用在线 API 时，医患对话和病历上下文会发送给所选服务商，使用真实患者数据前应完成隐私、授权和合规评估。

## 系统特点

- **纯本地运行**：患者数据、语音、病历全部保存在诊所电脑，不上传云端
- **AI辅助标注**：所有AI生成内容带颜色标识，诊断/治疗建议明确标注为"AI建议"
- **两步生成法**：先信息抽取 → 再病历生成，9B小模型也能稳定输出结构化病历
- **语音转写**：支持诊椅实时录音，自动转写为文字
- **录音文件导入**：可上传 MP3、WAV、M4A、WEBM、OGG、FLAC、AAC、WMA、OPUS、MP4 等常见录音格式
- **术语规范化**：自动将口语（"左边大牙疼"）转为医学术语（"26牙慢性牙髓炎"）
- **Word导出**：一键导出带颜色标注的Word病历，含电子签名区

## 部署步骤

### 第一步：安装 Python 环境

1. 安装 Python 3.10/3.11（[官网下载](https://www.python.org/downloads/）)
2. 安装时勾选 **"Add Python to PATH"**

### 第二步：准备 llama.cpp 服务

您已有 llama.cpp 部署的 Qwen3.5-9B，请按以下方式启动 HTTP 服务：

```bash
# 进入 llama.cpp 目录
# 启动 server（根据您的实际模型路径和量化格式调整）

# CPU模式（无独立显卡）
llama-server.exe -m qwen3.5-9b-q4_k_m.gguf -c 8192 --port 8080 -t 8

# CUDA模式（有NVIDIA显卡，推理速度快3-5倍）
llama-server.exe -m qwen3.5-9b-q4_k_m.gguf -c 8192 --port 8080 -ngl 35
```

参数说明：
- `-m`: 模型文件路径
- `-c 8192`: 上下文长度，病历生成需要较长上下文
- `--port 8080`: HTTP服务端口
- `-t 8`: CPU线程数，根据您的CPU核心数调整
- `-ngl 35`: GPU加载层数，有显卡时启用

启动成功后，浏览器访问 `http://localhost:8080` 应能看到 llama.cpp 的 WebUI。

### 第三步：安装病历系统

```bash
# 1. 解压项目到任意目录，如 D:\dental-ai-scribe
# 2. 打开命令提示符(CMD)，进入项目目录
cd D:\dental-ai-scribe

# 3. 创建虚拟环境（推荐）
python -m venv venv

# 4. 激活虚拟环境
venv\Scripts\activate

# 5. 安装依赖
pip install -r requirements.txt

# 6. 运行系统
python main.py
```

首次运行会自动下载 Whisper 模型（约150MB）到 `./models` 目录。

### 录音文件上传说明

- 默认最大文件大小为 **500 MB**，可在 `main.py` 中修改 `MAX_AUDIO_FILE_SIZE_MB`
- 上传过程采用分块写入临时文件，不会把整个大文件一次性读入内存
- 转写完成后临时文件会立即删除，原始录音不会由系统永久保存
- 当前版本未集成自动说话人分离。完整医患对话录音请选择 **“医患混合（未区分）”**，系统会保留这一不确定性，生成内容仍须医生审核
- 如需自动区分医生与患者，可后续集成说话人分离模型（例如 pyannote.audio）


### 第四步：使用系统

1. 浏览器访问 `http://localhost:8000`
2. 点击右上角 **"+ 患者"** 新建或选择患者
3. 可点击 **"开始录音"** 进行医患沟通，或将已有录音拖入 **"上传录音文件"** 区域
4. 实时录音时可切换 **"医生说"** / **"患者说"** 标签
5. 上传文件前可选择 **"医生录音"**、**"患者录音"** 或 **"医患混合（未区分）"**
6. 点击 **"停止录音"** 或完成文件上传后，系统自动在本机转写文字
7. 可多次录音或上传多个文件，积累对话记录
8. 点击 **"生成病历"**，等待15-30秒（长录音的转写时间取决于本机性能）
9. 在审核界面修改AI生成的内容（蓝色=AI生成，黄色=AI建议，红色=需确认）
10. 点击 **"保存病历"** 或 **"导出Word"**

## 知识库扩展

编辑 `kb/dental_knowledge.json`，按以下格式添加疾病知识：

```json
{
  "疾病名称": "疾病的定义、诊断标准、治疗方案等详细描述",
  "牙周炎": "牙周炎是牙周支持组织的慢性炎症...治疗：洁治、刮治..."
}
```

系统会自动根据对话内容匹配相关知识，辅助病历生成。

## 性能优化建议

### 如果生成速度太慢（>60秒）

1. **升级硬件**：加装独立显卡（RTX 3060 12GB即可显著提速）
2. **降低Whisper精度**：在 `main.py` 中将 `WHISPER_MODEL = "base"` 改为 `"tiny"`
3. **缩短对话**：录音控制在5分钟内，信息越集中生成越快
4. **模型量化**：使用 Q4_K_M 或 Q5_K_M 量化的模型，平衡速度和精度

### 如果转写准确率不高

1. **使用降噪麦克风**：诊椅高速手机噪音大，硬件降噪比软件更有效
2. **靠近麦克风说话**：建议医生佩戴领夹式麦克风
3. **升级Whisper模型**：将 `base` 改为 `small`（需要更多显存/内存）

## 常见问题

**Q: 点击生成病历后一直转圈？**
A: 检查 llama.cpp server 是否正常运行（浏览器访问 `http://localhost:8080`）

**Q: 生成的病历格式混乱？**
A: 9B模型偶尔会出现JSON格式错误，点击"保存"后手动整理即可。后续可通过微调模型改善。

**Q: 如何备份数据？**
A: 直接复制 `dental_records.db` 文件即可，这是完整的SQLite数据库。

**Q: 能否支持多诊室同时使用？**
A: 当前版本为单机版。如需多诊室，可将项目部署在诊所局域网服务器上，各诊椅电脑通过 `http://服务器IP:8000` 访问。
